# 合并到四个测试专家的接入说明

本 skill 设计为「被专家调用」，合并时在专家的 SKILL.md 中追加以下内容即可，无需改动专家既有步骤。

## 1. 需要埋入的两个钩子

### 钩子 A：生成 xmind 之后（提醒）

在专家流程中任何产出 xmind 用例的步骤末尾追加：

```
生成 xmind 用例后，调用 xmind-to-weknora skill 的「提醒模式」：
询问测试人员是否立即上传到 weknora 知识库。
- 回答「是」：进入执行模式（解析 -> 自动匹配 -> 确认卡 -> 上传）
- 回答「否」：用 sync_state.py 标记 pending，并在后续每个必做步骤收尾时再次提醒
```

### 钩子 B：每个必做步骤收尾（检查）

在每个必须执行的步骤结束前追加：

```
步骤收尾检查：执行 sync_state.py check --key "<用户故事>|<文档类型>"
- 退出码 10/12（pending/无记录）-> 输出提醒：
  「⚠️ 该需求的 xmind 用例尚未同步到 weknora 知识库（目标：<知识库名>）。
    终版确定后请说『上传知识库』，我会转成 Markdown 并归档。」
- 退出码 11（skipped）-> 提醒一次即可，不再重复追问
- 退出码 0（uploaded）-> 不打扰
```

## 3. 触发词建议

在专家 SKILL.md 的 description 或触发词列表中补充：

- `上传知识库` / `同步 weknora` / `归档用例` / `用例入库`
- `上传到知识库了吗` / `检查同步状态`
- `批量上传` / `批量归档` / `历史用例补录` / `把这个目录的用例都传上去`

批量场景的硬性要求（写进专家提示词）：**先向测试人员确认目录、业务线、产品、文档类型四项，再执行扫描；扫描只生成清单不上传，确认清单后才转换与上传。**

所有场景的硬性要求（写进专家提示词）：

1. **每次上传前必须展示确认卡**（业务线 + 对应专家 / 空间名称 + weknora空间ID / 知识库名 + 知识库ID / 文档类型 / weknora 标签 / 文档标题 / 来源文件 / 新建或更新），得到明确「确认」后才执行上传；沉默或答非所问视为未确认。
2. **优先用技能自动匹配的结果**，不要自行推测知识库；匹配结果与测试人员认知不一致时，以测试人员为准并回查映射。
3. **遇到映射里没有的知识库必须停下来问**：列出未登记知识库，请测试人员指定本次目标与归属业务线，登记并复核后再上传，禁止凭相似名称猜测。
4. **测试人员更正目标时**：改完目标重新展示确认卡，不在原目标上继续上传。
5. **MCP 连接器未配置时不硬试上传**：给出连接器配置清单（只需 `url` + `Authorization`，服务器名随意），停在配置步骤。
6. **不要让测试人员配置任何 json**：映射内置、新知识库由智能体写回内置预设。出现"请生成/修改 weknora_mcp.json"这类指引即视为误用（排障除外）。
7. **标签走方案 C：每条回执必提醒 + 进度追踪到闭环**：文档类型由技能自动判定（确认卡第 4/8 项 + 标题后缀 + MD 头部 `weknora标签`），但 weknora 标签**当前只能人工勾选**（MCP 无标签参数，实测结论）。每份上传完成后必须提醒：
   > ⚠️ 还需一步：请到 weknora 给该文档打上标签「<标签名>」
   > 知识库页（<知识库名>，空间：<空间名称>）→ 勾选该文档 → 「标签」→ 添加标签 → 选择「<标签名>」→ 确定
   > 打完请回复「已打标签」，我回写进度。

   进度用 `sync_state.py --tag` / `--tag-status`（批量用 `batch_cases.py mark --tag-status`）记录；每个步骤收尾 `check` 时若 `tag_reminder` / `untagged_total` 非空就继续提醒，最后一个必做步骤语气加强。批量模式在 B6 报告里输出按标签分组的勾选清单。详见 `weknora_tags.md`。
   **前提**：4 个标准标签（测试用例 / 测试总结 / 测试需求分析 / 测试缺陷）需先在各知识库建好，首次使用时提醒管理员或测试人员建一次。
8. **指定目标与预设不一致时必须停下来问**：路由返回退出码 3（未命中/未登记）或 4（与指定空间、业务线冲突）时，禁止凭相似名称凑一个库。先复述差异，再问测试人员：
   > 是 weknora 里新建了知识库吗？如果是，你只需告诉我一句「新增了 XX 库，归属 效贷 / 效融 / 泾渭云 / 小贷 / 智慧记零售 / AI进销存」，我来登记，不需要你配置任何 json。

   确认后走 `--diff-kb` → `--add-kb` → `--validate` + `resolve_target` 复核 → 确认卡 → 上传，并重新打包 skill 分发。

## 4. 版本与分发

- skill 目录：`xmind-to-weknora/`，随专家包一起分发或单独解压到 `~/.workbuddy/skills/`。
- **各小组需要准备的只有连接器配置**：`~/.workbuddy/mcp.json` 里加对应空间的 `url` + `Authorization`。路由映射已内置，不需要本地 json。
- 升级时同步替换整个 skill 目录即可。内置预设（`assets/preset_kb_mapping.json`）随包更新，是全团队唯一映射来源；如某台机器曾为排障生成过本地覆盖（`~/.workbuddy/weknora_mcp.json`），升级前应删除，否则会盖住新预设。
