# AI Testcase Workflow Skill

## 日常主流程

只围绕三件事工作：

1. 需求整理：读取用户提供的文档、页面信息、口述补充，持续更新需求整理稿。
2. 测试点/XMind：用户确认需求完成后，基于确认稿生成测试点 JSON 和 XMind。
3. Excel 用例：用户确认测试点后，基于 XMind/测试点生成详细测试用例 JSON 和 Excel。

默认不做知识库、不归档、不创建 `source/`、不创建整理索引、不生成厚重报告。

## 阶段门禁

| 阶段 | 触发 | 执行 | 禁止 |
|------|------|------|------|
| 需求整理 | 看下、整理一下、补充一下、结合页面、我再补充、先整理文档 | 读取输入源，更新需求整理稿，列待确认点 | 不生成测试点/XMind/Excel |
| 测试点/XMind | 文档完成、确认整理完成、开始生成测试点、生成 XMind | 基于确认稿生成测试点 JSON 和 XMind | 不读取知识库，不把待确认内容当规则 |
| Excel 用例 | 生成用例、生成 Excel、出详细用例 | 解析 XMind/测试点，生成详细用例 JSON 和 Excel | 不重复询问项目默认参数 |

## 必读 Prompt

进入某个阶段前，只读取对应 prompt：

| 阶段 | 文件 |
|------|------|
| 需求整理 | `prompts/document_consolidate.md` |
| 测试点/XMind | `prompts/testpoint_generate.md` |
| Excel 用例 | `prompts/testcase_refine.md` |
| 需求评审 | 仅用户明确要求评审时读取 `prompts/requirement_review.md` |

## 需求整理默认输出

```markdown
## 需求整理稿

### 背景/现状
### 目标
### 业务规则
### 流程/判断逻辑
### 影响范围
### 待确认点
### 本轮补充摘要
```

## 测试点结构原则

- 先在对话中给测试点结构预览；用户无异议后生成 JSON 和 XMind。
- 一级节点按需求功能点、业务场景或影响对象拆分。
- 功能点下面允许继续拆子功能点/子场景，直到能自然挂具体测试点为止。
- 正常流程、业务规则、边界组合、异常场景只是测试设计维度，不固定作为全局一级大模块。
- 目录节点只负责分组，叶子节点必须是可执行、可验证的具体测试点。
- 生成 XMind 前必须检查并消除空分类节点和分类节点叶子化。
- 从 XMind 生成 Excel 前必须复检叶子节点；叶子节点不合格时先输出问题清单，不擅自改名或脑补成新测试点。
- 不默认生成“兼容/回归范围”，除非需求或用户明确要求。

## Excel 参数规则

从 `{项目根}/.skill/project.yaml` 读取默认参数：

- `team`
- `product`
- `modulePath`
- `manager`
- `caseLevel`
- `source`
- `autoState`

用户只需提供：

- 用户故事标题
- 版本号
- 需求编码

`caseGroup` 从版本号和标题推导。

## 高级可选流程

日常流程不要启用以下能力。只有用户明确提出时才使用：

- 用户说“参考历史”“结合知识库”“同类需求”“历史用例”时，才按需读取少量历史资料。
- 用户说“入库”时，才读取 `prompts/knowledge_base_archive.md` 并执行入库。
- 用户说“归档”“生成整理版MD”“走完整流程”时，才执行正式归档、创建 `source/` 和整理索引。
