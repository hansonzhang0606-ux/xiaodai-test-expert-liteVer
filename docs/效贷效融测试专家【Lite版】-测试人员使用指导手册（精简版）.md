# 效贷效融测试专家【Lite版】 — 测试人员使用指导手册（精简版）

> **基于 v1.0.1 精简** | **适用对象**：效贷（XD）/ 效融（XR）/ 小贷（XXD）业务线功能测试人员 | **更新日期**：2026-09-02（安装方式改为 install.ps1 一键安装）
> 本精简版**只保留「首次使用操作步骤」+ 工作流 + 时间追踪 + 常见问题（QA）+ 三端使用说明**。完整背景、七环节规则、时间追踪细则见仓库内各 Skill 的 `SKILL.md` 与 `prompts/`。

## 一、首次使用操作步骤

### 第 1 步：一键安装（推荐，必做）

1. 打开 `https://github.com/hansonzhang0606-ux/xiaodai-test-expert-liteVer`
2. 点击 **Code → Download ZIP**，下载并解压到本地任意目录（如 `D:\xiaodai-test-expert-liteVer`）
3. 进入解压后的**仓库根目录**，找到 `install.ps1`
4. **完全退出 WorkBuddy**（Windows 托盘右键→退出；Mac Command+Q）
5. 右键 `install.ps1` → **「使用 PowerShell 运行」**（脚本自动把专家包写入 `my-experts` 并注册，运行完提示「安装完成」）
6. 重新打开 WorkBuddy → 进入【我的专家】即可看到「效贷效融测试专家【Lite版】」

> 说明：`install.ps1` 不依赖 WorkBuddy「添加团队市场」的自动注册（该流程在部分客户端版本不稳定，可能出现「点了 + 但专家不显示」），改为直接写入，确保稳定可用。脚本**幂等**，重装/升级重复运行安全。

### 第 2 步：通过团队市场安装（备选）

如果你更习惯用「添加团队市场」：左侧栏 **「专家·技能·链接」** → **「技能」→「套件」** → 右上角 **「+」** 填 `hansonzhang0606-ux/xiaodai-test-expert-liteVer` → 找到卡片点 **「+」** 安装。

> 该仓库已内置 `.codebuddy-plugin/marketplace.json` 市场清单。若此方式安装后【我的专家】未出现，请用第 1 步的 `install.ps1` 兜底（幂等，重复运行不会破坏已有配置）。

### 第 3 步：MySQL 初始化（AI 自动完成，无需手动开 CMD）

首次使用、身份验证通过后，AI 会自动检测本机配置——未初始化则自动生成配置模板（全空字段 + `mysql_config.notes.md` 备注说明），由你在本地文件按备注填写全部字段（host/port/user/password/database/table/charset/biz_line/biz_line_code）后回复「已填好」；已存在则跳过。**测试人员无需手动打开 CMD。**

- 生成配置路径：`C:\Users\<用户名>\.workbuddy\data\time-tracking\{业务线中文名}\mysql_config.json`
- ⚠️ 该文件**含数据库密码**，本机私有、不随包分发、不要发群/提交 Git；不初始化 = 时间数据只留本机、不同步团队库。

### 第 4 步：本机定时同步任务（AI 自动注册）

业务线确定后，AI 自动调用注册脚本在「任务计划程序」建好三个每日任务（早 09:00 / 午 12:00 / 晚 18:00），把本地 JSONL 幂等同步到团队共享 MySQL `agent_time_tracking` 表。已存在自动跳过，无需手动操作。

> Lite 版时间统计基于 **本地 JSONL + MySQL 共享库**（v5 已彻底移除腾讯文档依赖），因此**无需连接腾讯文档连接器**。

## 二、开始使用

1. **打开专家**：「我的专家」→「效贷效融测试专家【Lite版】」→「立即使用」。输入框预填欢迎语，直接发送。
2. **选择业务线**：首启时专家固定展示三项，输入数字选择本次处理的业务线：
   - `1` 效贷（XD）　`2` 效融（XR）　`3` 小贷（XXD）
   - 选定后整个会话归属该线（知识/时间/报告按业务线隔离）；**换业务线必须新开会话**，当前会话不自动切换。
3. **身份验证**：输入**真实姓名**（盲输入，实时查 MySQL `agent_team_roster` 花名册，精确匹配；不在名单联系管理员添加）。
4. **快捷入口**：3 个按钮（开始轻量版测试流程 / 根据已确认需求生成测试点和 XMind / 根据已评审测试点生成 Excel 用例），也可直接自然语言描述。

## 三、工作流（7 环节）

```
① 需求文档整理 → ② 需求评审（按需） → ③ 确认评审（按需）
                   ↓
④ 生成测试点与 XMind → ⑤ 评审 XMind（按需） → ⑥ 生成 Excel 用例 → ⑦ 知识库入库（按需）
```

| 步骤 | 你说的话 | 专家产出 | 你需要做的 |
|------|---------|---------|-----------|
| ① 文档整理 | "整理文档" / "提取这个 Confluence 页面" | 整理版 Markdown | 检查内容是否准确 |
| ② 需求评审（按需）| "评审这份需求" | 评审报告（6 维度） | 阅读评审报告 |
| ③ 确认评审（按需）| "确认" / "回写确认项" | 回写确认项的需求整理稿 | 人工确认后给出明确结论 |
| ④ 生成测试点 | "生成测试点" / "转 XMind" | 测试点 JSON + XMind 脑图 | 评审测试点 |
| ⑤ 评审 XMind（按需）| "XMind 评审完了" | 按评审意见更新的测试点 | 在 XMind 中修改测试点 |
| ⑥ 生成用例 | "生成用例" / "生成 Excel" | 测试用例 Excel | 检查用例准确性 |
| ⑦ 入库（按需）| "入库" / "归档" | 知识库更新 | — |

> 每完成一步，专家会停下来等你确认，不会自动跳转；日常默认主链路为 **① → ④ → ⑥**。
> 七个环节均可从合格的已有输入资产**独立启动**（如已有需求整理稿可直接说"生成测试点"），不强制重跑前序环节。

- **输出目录**：每次会话首次落盘产物时，专家会**询问并确认你的自定义输出目录**（不固定盘符），后续产出统一存入该目录。
- **业务线隔离**：所有产物、时间记录、统计报告均按首启选择的业务线（XD/XR/XXD）隔离，互不影响。

## 四、每步完成后记录节省时间（强制）

```
专家通报完成 → 展示参考时间 → 你回复时间 → 二次确认 → 记本地 JSONL → 定时同步 MySQL
```

| 步骤 | 参考节省时间 |
|------|------------|
| ① 文档整理 | 2~4 小时 |
| ② 需求评审 | 2~3 小时 |
| ④ 生成测试点 | 3~5 小时 |
| ⑥ 生成用例 | 4~8 小时（0.5~1 人天） |
| ⑦ 入库知识库 | 1~2 小时 |

> ⚠️ 环节 **③ 确认评审** 与 **⑤ 评审 XMind** 为人工操作环节，**不单独记录**节省时间。

- 你可以回复：`采纳`（取参考中间值）/ `4小时`、`0.5人天`、`3.5`（自行输入）/ 拒绝（最多问 2 次，记参考中间值并标注"用户未反馈"）。
- **查看统计**：随时说"查看时间节省统计" → 生成 HTML 报告（个人视角，含员工/步骤/故事/日期维度；管理员视角为业务线汇总）。

## 五、常见问题（QA）

**Q1：输入姓名后提示"不在花名册中"**
联系管理员将你的姓名添加到花名册（管理员直接 INSERT/UPDATE MySQL `agent_team_roster` 表，全团队即时生效）。注意输入**真实姓名**，不用昵称。

**Q2/Q3：安装后「我的专家」中看不到效贷效融测试专家【Lite版】**
首选确认已运行仓库根目录的 `install.ps1`（推荐安装方式，直接写入 `my-experts`）。若已运行仍看不到：检查 `C:\Users\<用户名>\.workbuddy\plugins\marketplaces\my-experts\plugins\` 下是否有 `xiaodai-testing-expert-lite` 目录、以及 `my-experts\.codebuddy-plugin\marketplace.json` 是否含 `xiaodai-testing-expert-lite` 条目；并**完全退出**（Windows 托盘右键→退出；Mac Command+Q）WorkBuddy 重新打开。若曾用「添加团队市场」安装失败，直接运行 `install.ps1` 兜底即可。仍异常联系管理员。

**Q4：专家找不到我的需求文档**
确保给的是**目录路径**或 **Confluence URL**，而非单个文件：
```
✅ 帮我整理 D:\项目文件\效贷\2026Q3\贷款审批优化 下的文档
✅ 提取这个 Confluence 页面：https://xxx/wiki/xxx
❌ 帮我整理贷款审批优化.docx
```

**Q5：XMind 文件怎么评审**
用 XMind 软件打开后直接修改（增删改节点、标记疑问），保存后告诉专家"XMind 评审完了"。

**Q6：时间反馈填错了怎么办**
二次确认环节直接说"不是 X 小时，是 Y 小时"修改；已保存的联系管理员在 MySQL 中修正。

**Q7：换业务线怎么用**
首启时选择本次业务线（效贷/效融/小贷），选定后整个会话归属该线。**换业务线必须新开会话**，当前会话不自动切换；各业务线数据隔离。

**Q8：换电脑了怎么办**
重新安装（下载仓库 ZIP → 运行 `install.ps1` → 重启 WorkBuddy）→ 首次使用身份验证通过后 **AI 自动重新生成 MySQL 配置模板** → 本地按备注填写密码。历史数据不丢（存在团队共享 MySQL）。

**Q9：专家更新了怎么更新本地**
重新下载仓库 ZIP，运行 `install.ps1`（幂等覆盖，无需先卸载）；或在「套件/专家」→「我安装的」→ xiaodai-testing-expert-lite 点「更新」。完成后完全退出 WorkBuddy 重开即可。

**Q10：新电脑上找不到 mysql_config.json**
正常现象（本机私有配置，不随包分发）。每台电脑首次使用身份验证通过后 AI 自动生成配置模板；或等专家引导初始化，按 `mysql_config.notes.md` 备注填写密码。

**Q11：为什么不用连接腾讯文档**
Lite 版时间统计基于本地 JSONL + 团队共享 MySQL（v5 已移除腾讯文档依赖），无需连接腾讯文档连接器，统计报告在本机浏览器/WorkBuddy 内直接打开。

**Q12：我负责多条业务线（如小贷+效融，也介入效贷）怎么用**
首启时专家请你从 效贷(XD)/效融(XR)/小贷(XXD) 中选择本次处理的业务线（按花名册实际归属过滤），选定后整个会话归属该线。多业务线请分别开会话处理，数据按业务线隔离。

## 六、在 Codex / VS Code 中使用（三端同源）

Lite 版同一套工程同时面向 **WorkBuddy、Codex App、Windows VS Code + Codex 扩展** 三端，业务规则与时间追踪完全一致。

- **Codex App**：打开本仓库，Codex 从 `.agents/skills/xiaodai-testing-expert-lite/SKILL.md` 自动发现入口，按七环节流程执行。
- **VS Code + Codex 扩展**：安装 Codex 扩展后打开本仓库，使用同一个 `.agents/skills` 入口；在终端调用 Python 脚本完成文档转换/XMind/Excel/统计报告。
- **身份与时间**：三端共用同一 MySQL 花名册与 `agent_time_tracking` 表；Codex/VS Code 侧的 MySQL 初始化与 WorkBuddy 侧一致（首次使用按提示在本地 `mysql_config.json` 填密码）。

> 详细三端差异与目录结构见仓库 `docs/三端使用说明.md` 与 `docs/架构与维护.md`。
