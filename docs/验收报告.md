# v1.0.0 验收报告

## 目标结论

同一套工程已具备 WorkBuddy、Codex App 和 Windows VS Code + Codex 扩展三种使用入口，不需要维护三套业务逻辑。根目录 `skills/` 为权威源码，WorkBuddy 目录、插件镜像和两个发布 ZIP 均由构建脚本生成。

## 兼容性边界

- WorkBuddy 需允许导入专家 ZIP、运行 Python 和访问团队 MySQL。
- Codex App 与 VS Code 需打开完整仓库根目录，才能发现 `.agents/skills` 入口及其平级 Skill。
- Windows 策略不允许创建计划任务时，业务流程和本地记录仍可使用，但需人工执行同步脚本。
- 使用 Excel 和文档转换前需安装 `requirements.txt` 中的依赖。

## 自动化证据

发布前执行 `python scripts/validate_release.py`，覆盖仓库契约、三端入口、敏感信息、ZIP 拓扑、姓名权限、计划任务、v5.9 回归和 Python 编译。发布 ZIP 采用固定时间戳和排序，连续构建的 SHA-256 保持一致。
